# CCASSO Scanner 2.3

Expo/React Native scanner for UniOrg attendance, membership cards, and Enrollment Fee receipts.

## What changed in 2.3

- The blue-and-white Sessions, QR Scanner, and Sync Center use the refined design.
- **Ready Check** tests the rear camera and UniOrg connection and shows the saved session, roster download time, and pending uploads.
- **Scan history** searches this device’s scans by name or student number. Open it from the scanner result or the **More** menu.
- **Guided review** provides next steps and a single-scan retry in Sync Center.
- **Live session totals** show confirmed attendance across all gates and this device’s pending scans for the selected session.
- Android preview APKs check GitHub for required updates.

## What changed in 2.2

- **Scanner modes** is the starting screen after setup. Select Attendance,
  Membership, or Enrollment Fee without re-entering the API token.
- Membership verifies the signed `UM1:` card against current server records.
  Expired, revoked, and invalid cards receive distinct results.
- Enrollment Fee verifies the signed `UE1:` receipt for an explicitly selected
  academic year. An authentic partial-payment receipt or a receipt from another
  A.Y. cannot display a fully paid confirmation.
- Both verification modes require an online server response. They do not record
  attendance, charge a student, or save verification requests in the offline queue.
- Attendance retains its existing session selection, offline queue, roster, and
  sync flow. Membership and receipt QRs are blocked in Attendance mode.

See [SCANNER_INTEGRATION.md](SCANNER_INTEGRATION.md) for setup, API contracts,
result meanings, and the device test checklist.

## What changed in 2.1

- Roster downloads now use server pagination, a longer roster-specific timeout,
  and compact chunked device storage for large student populations.
- A failed roster refresh keeps the previously completed offline roster intact.
- The Sessions screen now has a dedicated **Roster** action with clear success
  and failure feedback.
- Interface icons now use an app-sized curated subset of official Lineicons
  glyphs, avoiding the startup cost of bundling the complete catalog.

## Reliability improvements retained from 2.0

- A QR that remains in the camera frame no longer replaces a successful result
  with a misleading `ALREADY` message.
- Online attendance is displayed as accepted only after UniOrg explicitly
  returns `success: true`.
- Offline scans are labeled as queued and pending verification. They are not
  presented as server-confirmed attendance.
- Queue writes are serialized to prevent a camera scan and background sync from
  overwriting each other.
- Temporary network/server failures remain pending. Definitive validation
  failures move to **Needs review** and are never silently discarded.
- Background, reconnect, and manual sync operations share one sync lock, which
  prevents duplicate concurrent uploads.
- The last active session remains available after an app restart without a
  network connection.
- Setup, session selection, scanner, and sync center have a new professional,
  mobile-first interface.

## Connect to UniOrg

1. Open **Scanner Setup** in the app.
2. Enter the deployed UniOrg base URL, for example:
   `https://ccasso.azizomar.tech`
3. Paste an active Kiosk API token generated by UniOrg.
4. Give the scanner a unique device ID and gate label.
5. Tap **Verify & continue** while online to open **Scanner modes**. Select
   **Attendance** to load open sessions and download the offline roster, or open
   Membership / Enrollment Fee directly for online verification.

The scanner expects these UniOrg endpoints:

- `GET /api/kiosk/ping`
- `GET /api/kiosk/sessions?status=OPEN`
- `GET /api/kiosk/roster?limit=500&offset=0`
- `GET /api/kiosk/sessions/<id>`
- `GET /api/kiosk/sessions/<id>/stats`
- `POST /api/kiosk/scan`
- `POST /api/kiosk/scan/batch`
- `POST /api/kiosk/memberships/verify`
- `POST /api/kiosk/enrollment-receipts/verify`

All modes use the same active Admin-generated Kiosk API token in
`Authorization: Bearer <token>`. Keep the token on the scanner; it does not
belong inside student QR codes. Revoking it in the Admin Panel blocks all modes.

## Run in Expo Go

The light mobile UI follows the design in
`output/imagegen/ccasso-mobile-ui-concept-v5.png`. Sessions, QR Scanner and Sync
Center share the same blue actions, white cards, metric strips and bottom
navigation. Setup uses the same visual system. Session names, counts, roster,
scan results and queue entries come from the connected UniOrg server and device
storage.

```cmd
npm install
npm run start:go -- --clear
```

Open **Expo Go** on your phone and scan the QR code displayed in the terminal.
Keep the phone and computer on the same Wi-Fi network. This project uses
**Expo SDK 54**; install the matching Expo Go version from
[Expo's official download page](https://expo.dev/go?device=true&platform=android&sdkVersion=54)
if your phone reports a version mismatch.

If the network blocks the LAN connection, use `npm run start:tunnel` (Expo may
offer to install its tunnel helper). To inspect the interface in a browser, run
`npm run web`; web preview dependencies are included.

In the scanner, **Enter student number** opens manual entry and roster search.
**More** contains speed/quiet/offline controls, roster download, recent scans,
export, the session PIN and event summary. Offline results remain amber and
pending until UniOrg confirms them. Sync Center retains rejected scans under
**Needs review** and leaves temporary failures pending.

Expo Go runs the app for development; it does not produce an APK. The APK build
command is below.

Square icon build variants live in `assets/icon-square.png` and
`assets/adaptive-icon-square.png`. If the source logos change, regenerate the
variants with `node scripts/prepare-icons.cjs`.

## Build an Android APK

```cmd
npm install
npx eas-cli login
npm run build:apk
```

The `preview` profile produces an installable APK. The `production` profile in
`eas.json` produces an Android App Bundle for Play Store release.

When EAS finishes, open the build's install link on your Android phone, download
the APK and allow installation from that browser when Android prompts. The
installed app starts on its own; Expo Go and a running Metro server are not
required. Connect it to UniOrg in Scanner Setup as described above.

`.easignore` excludes local previews, verification fixtures, generated design
images and signing files from the uploaded source archive.

## Publish a required Android update

1. Build the release APK using `npm run build:apk` and the same Android package
   ID and signing key as the APK currently distributed to users.
2. Publish a stable release on
   [GitHub Releases](https://github.com/Aziz-coder0/ccasso-scanner/releases)
   with the matching version tag, such as `v2.3.0`. Attach the signed preview
   APK. Use `CCASSO-Scanner-2.3.0.apk` as its name if you publish more than one
   Android APK in the release.
3. Install the 2.3.0 APK on existing devices as the initial rollout. For each
   later release, increase the app version and Android `versionCode` before
   building. For example, publish `v2.3.1` with `versionCode` 7.

The preview APK checks for the latest stable release at startup, on return to
the app, and every five minutes while active. A newer release with an installable
APK shows **Update required** and blocks scanning until the new APK is installed.
Install it over the existing app to keep the offline queue and setup. An
unreachable release check uses the last known update state, so a device starting
offline can keep scanning if it has never detected a required update. Expo Go,
local test APKs, iOS and Play Store builds use their own distribution paths.

## Local standalone test APK

With Java 17 and the Android SDK installed, run:

```cmd
npm run android:apk:local
```

This builds `output/apk/CCASSO-Scanner-2.3.0-local-test.apk` with the label
**CCASSO Scanner** and package `org.ccasso.kioskscanner.local`. The release
variant includes the app's JavaScript and assets, so it runs without Metro or
Expo Go. It uses the existing Android debug/test signing key for local testing.

Install it beside the original app, then enter the deployed server URL and an
active Admin-generated API token in **Scanner Setup**. Its settings, roster,
and attendance queue are separate from the original app. Keep using the original
app to synchronize any attendance still pending there. This test APK does not
replace the EAS-signed app; `npm run build:apk` remains the EAS preview workflow.
Building the APK does not confirm installation or camera behavior on a phone.

## Local Android development build

This project uses npm and includes `expo-dev-client`. Java 17 and the Android
SDK are required. On this Windows machine, the build tools are installed under
`C:\Users\Public\ExpoAndroid`, with `JAVA_HOME` and `ANDROID_HOME` configured
for the current Windows user. Open a new terminal after installing these tools.

Connect an Android phone by USB, enable Developer options and USB debugging,
then approve the computer's debugging prompt on the phone.

```cmd
npx expo prebuild --clean --npm
npx expo run:android --device
```

After the development build is installed, start Metro with `npx expo start`
or `npm run start:dev`. `npm run start:go` still opens the Expo Go workflow.
Regenerate with `npx expo prebuild --clean --npm` and rebuild after changing
native dependencies or `app.json`. JavaScript-only UI changes need only Metro.
Generated `android` and `ios` folders are ignored; EAS regenerates them from
the app configuration for cloud builds.

For this Windows workspace, `npm run android:device` applies the Java UTF-8
and temporary-folder settings needed by the local build tools. For long or
non-ASCII workspace paths, it refreshes a native build copy under
`C:\Users\Public\ExpoAndroid\ccasso-scanner`, then invokes
`expo run:android --device`. To compile a development APK without a connected
phone, use `npm run android:apk`; it copies the result to
`output/apk/CCASSO-Scanner-2.2.0-development.apk`. Metro runs from the main
workspace so live JavaScript changes use your current source. Add `-- -Clean` to either
script after native dependencies or app configuration change. Development
APKs load JavaScript from Metro; use the local standalone test APK above or the
EAS preview APK for use without Metro.

## Scan result meanings

- **PRESENT / LATE** — confirmed by the UniOrg server.
- **ALREADY** — UniOrg confirmed that the student was already marked, or the
  exact scan is already waiting in this device's offline queue.
- **QUEUED** — saved safely on the device; UniOrg verification is pending.
- **ERROR** — rejected by UniOrg or invalid for the selected session.

Do not clear the Pending list until it has synchronized. Clearing local data
cannot undo attendance already accepted by UniOrg.
